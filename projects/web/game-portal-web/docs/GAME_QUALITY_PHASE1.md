# Game Shelf ゲーム品質改善・第1段階

更新日: 2026-10-04

## 今回の対応

優先度高の6項目を対象とする。別開発中のカラーチェイン、内包される将棋・麻雀のゲームロジックは変更しない。既存の未コミット変更は保持する。

1. **数独**: 複数解だった上級問題に9個の手掛かりを追加。問題IDを hard-01-v2 とし、旧問題の記録と分離する。全9問の解が一意であることを検査する。完成判定は模範解答との単純一致ではなく、初期数字を守り、行・列・3×3区画が数独の規則を満たすかで行う。赤表示とカウントは数字の重複を示す。
2. **マインスイーパー**: 初手前の旗操作では開始状態を進めない。実際にマスを開く時だけ地雷を配置する。旗のあるマスや開いたマスでは配置しない。ランダムな地雷配置をReactの状態更新関数外へ移動し、開発用StrictModeの再呼出しに影響されないようにする。クリア時間と保存時間を一致させる。
3. **神経衰弱**: 判定待ちタイマーをリセット・難易度変更・画面離脱で解除する。旧ゲームのカードIDを新盤面へ適用しない。ペア判定と記録保存の副作用を状態更新関数の外へ出す。最終ペア判定時の時間を表示・ベスト・ランキングで揃える。
4. **スネーク**: 実際に進んだ方向と次の移動方向の予約を分離する。1ティックにつき方向変更は1回とし、上→左の連続入力で右進行から逆走することを防ぐ。
5. **言語切替**: 日本語への復元は切替時の一度だけ。古い原文を後続のゲーム表示へ繰り返し書き戻さない。予約済みの翻訳処理は切替・離脱時に解除する。動的なaria-labelなどの変更も翻訳元へ反映する。既存の data-native-i18n 除外設定は保持する。
6. **保存の耐障害性**: ポータルと公開内蔵ゲームの保存アクセスを safeStorage に集約する。保存拒否・容量不足・削除失敗ではタブ内の一時保存へ切り替え、案内を日英表示する。既知の記録形式についてJSON構文だけでなく値の型も検査する。不正な元データは自動削除せず、読み込み時は未記録扱いにする。

## 記録の扱い

- 正常な既存記録・お気に入り・最近遊んだ履歴は同じキーで継続利用する。
- 上級数独の改訂前記録は削除しないが、改訂版のベストやランキングには流用しない。
- 保存不可時の一時データはページ再読み込み・タブ終了で失われる。通知で明示する。
- 不正な記録を読み込んだ時点ではディスク上の元データを消さない。そのゲームで新しい記録を保存すると通常どおり上書きされる。
- ランキングは従来どおりそのブラウザに保存されるローカルランキングであり、オンライン共有への変更はない。
- 完全な翻訳方式の移行は別段階。今回はDOM翻訳の既知の上書き不具合を修正する。

## テストの実行

プロジェクトディレクトリで実行:

```powershell
npm run test:portal-core
npm run test:color-chain
npm run test:color-chain-rotation
npm run test:color-chain-map
npm run build
```

ブラウザテストは、別ターミナルでローカルサーバーを起動してから実行:

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4180 --strictPort
npm run test:portal-browser
```

- ワークスペースの random-shogi-web に既存のPlaywrightと、インストール済みMicrosoft Edgeを使用する。新しい依存パッケージは追加していない。
- 別配置では PORTAL_PLAYWRIGHT_MODULE にPlaywrightのモジュールURL、PORTAL_TEST_URL に対象ローカルURLを指定できる。
- 隔離したブラウザ環境を使い、対象origin以外の通信を遮断するため、解析のページビューは送信しない。
- 数独9問の一意解、正当な別解の完成判定、保存の正常・異常系を自動検査する。
- ブラウザでは旗操作・リセット・二重方向入力・日英切替・改訂上級数独の日英クリアを検査する。
- 公開内蔵34ゲームは390×844で通常・保存拒否・不正保存データの3条件を起動確認する。不正データの画面テストは反射神経テスト・イラストロジック・ブラックジャックの異常データを投入する。数独の保存形式はロジックテストで検査する。
- これは全ゲームの全難易度完走、実スマートフォン、公開サイトへの反映を保証するテストではない。

## 次段階（第2段階の実施記録は GAME_QUALITY_PHASE2.md を参照）

優先度中を次の順で進める。

1. 難易度変更時に前回の勝利結果を別難易度へ登録できる問題（三目ならべ等）の対策。
2. 2048の名前入力中のキー競合と、開発用StrictModeのスコア二重加算を修正。
3. Simon Saysの完走スコア表示とランキングの不一致を修正。
4. 反射神経テストの記録リセット時の待機タイマー解除。
5. 時間制ゲームの残り時間を実経過時間基準へ統一し、バックグラウンド復帰時を検証。
6. イラストロジックなどのキーボード操作・フォーカス表示を補完。
7. 今回対象外のゲームの最終結果値・保存値・ランキング値を引き続き統一。

その後、DOMを後から置き換える翻訳から各ゲームの直接的な日英表示へ段階的に移行する。ヒント利用時の記録分離・途中保存・記録削除確認などの仕様改善は別段階で扱う。
